# 야자 관리실

야간자율학습 시간을 관리형 독서실처럼 관리해 주는 웹앱입니다.
인터넷 주소로 올려 두면 휴대폰 홈 화면에 **앱처럼 설치**할 수 있고, 한 번 연 뒤에는 인터넷이 없어도 열립니다.

- **오늘**: 할 일 계획(과목·범위·예상 시간) → 타이머 → 점검(결과·집중도·방해 요인)
- **기록**: 달력에서 날마다 순공 시간과 점검 내용 확인
- **보고서**: 주간 순공, 목표 달성률, 계획 정확도, 시간대별 집중도, 방해 요인, 다음 주 제안(근거 포함)
- **설정**: 과목·방해 요인 수정, 실험 단계(A주/B주), 기록 내보내기(CSV), 백업, 베타 기록 보내기

## 들어 있는 파일

| 파일 | 하는 일 |
|---|---|
| `index.html` | 앱 화면의 뼈대 |
| `styles.css` | 디자인 |
| `app.js` | 앱 기능 전체 |
| `config.js` | 운영팀 설정 (구글 시트 수집 주소) |
| `manifest.webmanifest` | 앱 이름·아이콘 등 설치 정보 |
| `sw.js` | 오프라인 실행용 서비스 워커 |
| `icons/` | 앱 아이콘 |
| `apps-script/Code.gs` | 베타 기록을 구글 시트로 받는 코드 (사이트에는 안 올려도 됨) |

---

## 1. 인터넷 주소로 올리기 (GitHub Pages, 무료)

1. GitHub에 로그인하고 오른쪽 위 **+ → New repository**를 누릅니다.
2. 이름을 정하고(예: `yaja-room`) **Public**으로 둔 뒤 **Create repository**를 누릅니다.
3. 새 저장소 화면에서 **uploading an existing file**을 누르고, 이 폴더 안의 파일과 `icons` 폴더를 통째로 끌어다 놓습니다. 그다음 **Commit changes**를 누릅니다.
4. 저장소의 **Settings → Pages**에서 Source를 **Deploy from a branch**, Branch를 **main / (root)**로 정하고 **Save**를 누릅니다.
5. 1~2분 뒤 `https://<GitHub 아이디>.github.io/<저장소 이름>/` 주소로 앱이 열립니다.

> 서비스 워커(오프라인 실행)와 앱 설치는 `https://` 주소에서만 동작합니다. 파일을 컴퓨터에서 바로 열면 기본 기능만 됩니다.

## 2. 휴대폰에 앱으로 설치하기

- **안드로이드(Chrome)**: 주소를 열면 나오는 **앱 설치하기** 버튼을 누르거나, 메뉴(⋮) → **앱 설치** / **홈 화면에 추가**를 고릅니다.
- **아이폰(Safari)**: 아래쪽 공유 버튼 → **홈 화면에 추가**를 고릅니다. 아이폰은 Safari에서만 설치할 수 있습니다.

> 아이폰은 Safari와 홈 화면 앱의 저장 공간이 따로입니다. **먼저 설치하고, 그다음부터는 홈 화면 아이콘으로만** 쓰도록 안내해 주세요.

기록은 각자 휴대폰의 앱 안에만 저장됩니다. 기기를 바꾸기 전에는 설정 → 백업 코드 복사로 옮길 수 있습니다.

## 3. 베타 테스트 기록을 구글 시트로 모으기 (선택)

테스터들이 CSV를 따로 보내지 않아도, 점검을 저장할 때마다 운영팀 구글 시트에 자동으로 한 줄씩 쌓이게 할 수 있습니다.

1. 구글 시트를 새로 만듭니다(예: `야자 관리실 베타 기록`).
2. 메뉴 **확장 프로그램 → Apps Script**를 엽니다.
3. 원래 있던 코드를 모두 지우고 `apps-script/Code.gs` 내용을 붙여 넣은 뒤 저장합니다.
4. 오른쪽 위 **배포 → 새 배포** → 유형 선택(톱니)에서 **웹 앱**을 고릅니다.
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
5. **배포**를 누르고 권한을 허용합니다. "Google에서 확인하지 않은 앱" 화면이 나오면 **고급 → (프로젝트 이름)(으)로 이동**을 누르면 됩니다.
6. 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사합니다.
   브라우저에서 이 주소를 열어 `수집 주소가 정상적으로 동작하고 있어요`가 보이면 성공입니다.
7. GitHub 저장소에서 `config.js`를 열고 연필(편집) 버튼을 눌러 `submitUrl: ''`의 따옴표 안에 주소를 붙여 넣은 뒤 **Commit changes**를 누릅니다.
8. 테스터는 앱 **설정**에서 참여 코드를 넣고 **내 기록을 운영팀 구글 시트로 보내기**를 켭니다.

시트에는 `점검기록`(타이머 한 번 = 한 줄)과 `할일`(계획 한 개 = 한 줄, 상태가 바뀌면 갱신) 탭이 자동으로 생깁니다.
같은 기록이 두 번 와도 한 번만 들어가고, 인터넷이 끊겼을 때 저장한 기록은 다시 연결되면 자동으로 보내집니다.

> `Code.gs`를 나중에 고쳤다면 **배포 → 배포 관리 → 편집(연필) → 버전: 새 버전 → 배포**를 해야 같은 주소에 반영됩니다.

## 4. 베타 테스트 진행 예시

1. 테스터마다 참여 코드(예: T01, T02 …)를 정해 줍니다. 실명은 쓰지 않습니다.
2. **1주차**: 설정 → 실험 단계 **A주: 기록만**. 보고서와 피드백 없이 기록만 쌓습니다.
3. **2주차**: 실험 단계 **B주: 피드백**. 점검 피드백과 주간 보고서를 보여 줍니다.
4. 시트(또는 CSV)의 `실험단계` 열로 A주와 B주를 나눠 목표 달성률, 계획 정확도, 집중도, 방해 요인 빈도를 비교합니다.

> 인원이 적고 대조군이 없으며, 처음 써 보는 앱이라 생기는 효과도 섞일 수 있습니다. 결과를 발표할 때 이 한계를 함께 밝혀 주세요.

## 5. 고치고 다시 올리기

GitHub 저장소에서 파일을 수정(연필 버튼)하거나 새 파일을 다시 업로드하면 1~2분 뒤 반영됩니다.
설치된 앱은 다음에 인터넷이 연결된 상태로 열 때 새 버전을 받습니다.

- 기본 과목과 방해 요인 목록: `app.js` 위쪽의 `DEFAULT_SUBJECTS`, `DEFAULT_DISTRACTORS` (각자 앱의 설정 화면에서도 바꿀 수 있음)
- 앱 이름·색: `manifest.webmanifest`, `styles.css` 맨 위의 색 값

## 6. 개인정보

- 기록은 기본적으로 각자 기기에만 저장되고 어디에도 보내지 않습니다.
- 기록 보내기를 켠 경우에만 다음 항목을 보냅니다: 참여 코드, 실험 단계, 날짜·요일·시각, 과목, 예상·실제·휴식·이탈 시간, 결과, 집중도, 방해 요인.
- **닉네임, 할 일 제목, 메모는 보내지 않습니다.**
- 베타 테스트 전에 참여 동의서를 받고, 수집 주소는 테스터에게만 공유해 주세요.

## 7. (선택) 안드로이드 앱 파일로 만들기

사이트를 올린 뒤 PWABuilder(pwabuilder.com)에 주소를 넣으면 이 웹앱을 안드로이드 앱 패키지로 만들 수 있습니다.
Play 스토어에 올리려면 Google Play 개발자 계정(유료)과 심사가 필요합니다. 학교 안 베타 테스트라면 홈 화면 설치만으로 충분합니다.
